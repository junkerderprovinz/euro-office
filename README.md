## 2. What it does

[Euro Office](https://github.com/euro-office/documentserver) is a European fork of the OnlyOffice Document Server. It edits Word, Excel and PowerPoint files and their OpenDocument counterparts in the browser, and it speaks the OnlyOffice and WOPI APIs, so OpenCloud, Nextcloud and ownCloud can use it. It is the editor behind a file server, not an app of its own. This image is the upstream [`ghcr.io/euro-office/documentserver`](https://github.com/euro-office/documentserver/pkgs/container/documentserver) with four additions:

- **It repairs the `Data` folder.** The upstream build leaves out the step that hands `Data` to the user its services run as, so on a fresh Unraid folder the admin panel, and sometimes editing, fail with a permission error. A small program fixes the ownership in the first seconds of every start. The report that found it is [unraid-apps#7](https://github.com/junkerderprovinz/unraid-apps/issues/7).
- **It runs under OpenCloud's address.** The [OpenCloud](https://github.com/junkerderprovinz/opencloud) container passes the editor through at `/euro-office/`, and this image strips that prefix again. The browser only talks to OpenCloud, so plain http between the two containers is fine, there is no certificate to accept, and only OpenCloud has to be reachable from outside.
- **It serves https for other clouds.** Nextcloud and ownCloud load the editor straight from Euro Office, so the image makes a self-signed certificate on the first start, or uses yours. The http port keeps serving the editor instead of redirecting to the Unraid web UI.
- **Its start page helps.** It replaces the vendor's page and says whether the editor is ready and which three fields to set in OpenCloud.

## 3. Getting started

1. Install **Euro Office** from [Community Applications](https://ca.unraid.net/apps/euro-office-01m59u11rtj6n9), set a long random **JWT secret** and click **Apply**. The first start takes a minute or two.
2. Open the WebUI at `http://<server-ip>:9900`. The start page says when the editor is ready.
3. In the OpenCloud template, set these three fields and apply:

| OpenCloud field | Value |
|---|---|
| **Web office suite** | `euro-office` |
| **Office document server URL** | `http://<server-ip>:9900`, the address the WebUI button opens |
| **Office WOPI secret** | the same text as the **JWT secret** here |

The **New** button in OpenCloud then offers documents, spreadsheets and presentations, and Office files open in Euro Office. This needs the OpenCloud container 1.4.0 or later. An older one loads the editor straight from Euro Office and needs its https address, `https://<server-ip>:9943`.

Without Unraid:

```bash
docker run -d --name euro-office \
  -p 9900:80 \
  -e WOPI_ENABLED=true \
  -e JWT_ENABLED=true \
  -e JWT_SECRET=change-me-to-a-long-random-string \
  -e USE_UNAUTHORIZED_STORAGE=true \
  --restart unless-stopped \
  ghcr.io/junkerderprovinz/euro-office:latest
```

Nextcloud and ownCloud need the https port as well (`-p 9943:443`, **HTTPS Port** under Advanced View in the template). Accept its certificate once on every device, or put a certificate your browsers trust in the **Certificates** folder and fill in **TLS certificate** and **TLS private key**. Leave **Logs** and **Database** empty: an empty folder mounted there hides what the image ships, and the container cannot start.

## 4. How AI is used here

One knight builds this, and AI is one of the tools I work with, the same way I work with an editor or a compiler. It helps me write code and documentation and it checks my work, and that saves me a good many evenings. It does not make the decisions, though. I read and understand everything before it ships, and if something here breaks, that is on me and not on the tool.

You do not have to take my word for it. The code is open and every release note is written by hand. The issue tracker shows how problems actually get handled, including the ones I got wrong the first time. If you find something that is not right, open an issue and I will look at it.
